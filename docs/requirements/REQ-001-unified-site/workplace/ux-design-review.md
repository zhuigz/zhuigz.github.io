## 风险清单

### [blocker] UX-001 · 移动端 chapter-rail 隐藏后验收第 5 条可能缺口

**位置**:tech-design KD-5 / T5.3 注意事项  
**描述**:方案在 768px 隐藏 `.chapter-rail`,兜底方案是"顶部进度条 + 当前章名",但 T5.3 只说"可用顶部章名替代",未锁定具体实现形式,也未说明章名如何跟随 `body[data-chapter]` 变化。若执行阶段遗漏,移动端用户滚动到第 5 章时无法感知自己在哪里,也无法跳章——验收第 5 条"任意位置可见当前章 + 可跳任意章"直接失败。  
**建议**:在方案中将移动端导航方案具化为两种可选形态之一并锁定:① 768px 下 rail 折叠为底部可展开抽屉(点击展开跳章);② 768px 下 rail 隐藏,顶部固定栏显示当前章名(通过 `body[data-chapter]` CSS 切换 `content` 或 JS 写文本)。二选一并写入 T5.3,让执行有明确产物而非"可用 X 替代"的模糊指引。

### [major] UX-002 · 相邻章 rootMargin 中带判定的视觉抖动风险低估

**位置**:tech-design KD-2 / T1.4 / R3  
**描述**:方案用 `rootMargin: '-45% 0px -45% 0px'`(中带 10% 高度)判定当前章。10 章中内容量差异大:序章/终章(≤16KB)高度远低于六章/七章(≤30KB)。当短章(序章/信念/终章)高度接近或小于一屏时,短章和相邻章可能同时满足"穿越视口中线"的判定条件——极端情形下 observer 回调同帧有两个 entry 均 `isIntersecting`,虽然方案要求取 `intersectionRatio` 最大者,但过渡动画(`transition: 1.2s`)仍会被触发两次(连续写两次 `body.dataset.chapter`),用户会看到背景在 1.2s 内连跳两个色温值。  
**建议**:① 为短章(预期高度 < 1.5vh 屏)设置 `min-height: 100svh` 保障至少一屏纵深,避免"穿不过中线就离开"的情形;② 场景引擎加去抖(16ms debounce 或 `requestAnimationFrame` 节流):若同帧收到多个 entry,只提交一次 `dataset.chapter` 写入;③ 在 T1.4 注意事项中明确"连续章同帧命中"的处理逻辑。

### [major] UX-003 · 六章三源内容去重策略依赖执行者自判,缺乏结构性约束

**位置**:tech-design T3.3 注意事项 / R5  
**描述**:六章(系统)整合 growth + system + prosper 三源,繁荣公式/AI 杠杆/长期主义在三源中各有独立段落。方案说"只放一次权威表述"并给出分层叙述规则,但这是叙事决策,不是代码约束——执行阶段 Dev 逐段提取时极易在不同子区块里"顺手"带入同义内容。若去重失败,六章单独体量可能逼近或超 30KB,且阅读时读者会感受到"绕圈子"的叙事疲劳。  
**建议**:在预算表"六 系统"行增加"禁止重复项"清单(明确列出:繁荣公式只出现在 `#ch6` 第一屏;AI 杠杆/长期主义只在哲学层做一句引用,不展开;growth 五子系统详解≤3 句/项),让 Dev 有可检查的约束条目而非原则陈述。运行时验收时 UX Evaluator 按此清单逐项核查。

### [major] UX-004 · canvas 粒子在长页的"熄灭后不再点燃"风险影响终章体验

**位置**:tech-design T5.2 / R4  
**描述**:方案已识别 R4(canvas opacity 绑定首屏滚动比例失效),但 T5.2 的缓解策略是"改为按章判定",具体实现留给 Dev 自定。如果实现为"序章可见→运行,其余章停机",则终章的"万丈光收束"依赖 canvas 满金粒子爆发——而用户从中部章节(如六章/七章)直接跳章至终章时,canvas 处于停机状态,视觉上终章光效减弱,与"满金收束"的设计意图相悖。  
**建议**:明确 canvas 运行逻辑为"序章 OR 终章(ch9)可见→高密度运行;其余章低密度(≤30 粒)运行而非完全停机"。`stop()`逻辑只用于完全不可见的章节,不用于"叙事上需要光效高潮但当前并非首屏"的终章。此逻辑应在 T5.2 锁定而非留给执行隐性决定。

### [major] UX-005 · 七色光谱(底色章)引入调色板外颜色的风险未被封堵

**位置**:tech-design T2.2 注意事项  
**描述**:方案说"颜色从 `--scene-*` 体系内取或克制使用 index 既有 accent 变量",但光谱本身语义上需要 7 种可区分色相(红橙黄绿青蓝紫),而 index 调色板只有 gold/ember/violet/teal/sage 5 个辅助色,缺少"红"和"橙"的独立变量。执行阶段 Dev 极可能自行引入 `#E05050`(红)、`#E07830`(橙)等硬编码颜色——单章的视觉亮点变成调色板例外,在 reduced-motion/低对比度场景下尤为突兀。  
**建议**:在 T2.2 中预先声明:① 光谱用 `background: conic-gradient(from 0deg, ...)` 单个 CSS 渐变实现七色,**不用 7 个独立色块 div**,这样无需引入 7 个新变量;② 若用色块,ember 代表红橙区,gold 代表黄橙区,sage/teal/violet 代表绿青蓝区——明确映射关系,避免调色板污染;③ 光谱图案在 reduced-motion 下静止呈现即可,不需要动画。

### [minor] UX-006 · reveal-stagger 延迟分组在长时间线章节未锁定

**位置**:tech-design T2.3 注意事项  
**描述**:方案提到时间线四幕可拆 ~10 子节点,并指出"nth-child 超过 11 个走兜底"(index 第 471 行),建议"分组包裹避免末节点延迟过久"——但这只是注意事项而非约束。若执行阶段未分组,第 10 个子节点入场延迟会叠加至 ~2s 以上,用户滚动到中途就已完整越过时间线,最后几个节点入场时用户已不在视口,体验上时间线"尾部消失"。  
**建议**:在 T2.3 中规定:每幕(4 幕)作为独立 `.reveal-stagger` 容器,幕内子节点数 ≤5;幕与幕之间间距由父级 `.reveal` 控制,而非连续 nth-child 延迟。这样最大累积延迟 ≤5×0.12s = 0.6s,节奏可控。

### [minor] UX-007 · 序章"重新演绎不复制 index hero"的体验边界未定义

**位置**:tech-design T1.5 注意事项 / prd.md 序章行  
**描述**:方案要求"重新演绎,不复制 index hero DOM",但没有说明演绎方向——是更简洁(一点光扩散后单行名字)还是更复杂(多层光效叠加)。缺少约束时执行阶段可能在序章投入过多 DOM 与动画层(复刻 hero 的 god-ray + orb + canvas 全套),导致序章体量超 16KB 预算,且与 index.html 首屏视觉高度相似、失去"全新开场感"。  
**建议**:在 T1.5 补充序章视觉约束:① DOM 元素数量参考:名字 + 别名 + 使命 + 座右铭 4 个文字层 + 背景光点,共 ≤8 个显著 DOM 节点;② 光效只用 preloader 结束后残留的"一点光扩散"纯 CSS,不在序章重新启动 god-ray/orb(它们是全局贴层,序章让全局贴层"冷启动"即可);③ 明确"重新演绎"的差异点:入场节奏比 index hero 慢 30%,营造"长廊开门"而非"个人名片亮相"的氛围。

### [minor] UX-008 · "光"母题在 reduced-motion 下的视觉连贯性未被验证

**位置**:tech-design T5.4 / prd.md 体验要求  
**描述**:方案的 reduced-motion 策略是"transition 归零 + canvas return + 飞轮/光束停",内容完整性验收第 7 条可以通过。但 PRD 体验要求说"光母题贯穿各章",在 reduced-motion 下背景色瞬切、canvas 熄灭、光束停止后,各章之间的视觉区分度大幅下降——10 章在静态模式下可能呈现为"深色背景上不同色温的文字块",色温差异仅靠 `--scene-bg` 的硬切来表达。  
**建议**:在 T5.4 补充 reduced-motion 下的"光母题保留策略":① 每章保留一个静态 CSS 径向光晕(纯 `background: radial-gradient`,无 animation,只读 `--scene-glow`),即使所有动画关闭,各章的光色气质仍可通过静止光晕区分;② 章节标题旁的色条/光色眉题(如 `.section-label` 的颜色)用 `--scene-glow` 着色,在静态下也能传递章节色温信息。
