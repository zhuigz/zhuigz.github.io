# REQ-001 — 集大成网站:追光者全集

状态:designing 完成 · 决策记录见 `workplace/kickoff.md` · 2026-06-11

## 背景与动机

站点已积累 12 个各自成熟的独立页面(说明书、回忆录、底色、目标、FIRE、成长体系、人生系统、繁荣公式、IDOP、工作流、HKRR、AI 信)。单页时代是因为体系尚未成熟;现在体系已经完整,要把它们**内容级整合**(非链接跳转)为一个集大成作品——内容丰富度与视觉震撼度都要超越既有任何单页。

## 目标

1. 产出一个全新的独立页面(文件名 **`opus.html`**,寓意 magnum opus 集大成之作;PM 可在 executing 前改名),将 12 个内容源的精华融合为一部连贯的"人生叙事弧"作品
2. 视觉形态为**沉浸式滚动叙事**:滚动驱动场景演变,读者像走过一条光的长廊——"光"是贯穿全页的视觉母题(呼应"追光者"人格品牌)
3. 阅读体验完整自洽:从序章到终章一气呵成,任何设备上都可完整阅读

## 范围

### In Scope

- 新建 `opus.html`(完全自包含:HTML + 内嵌 style + 内联 script)
- 12 个内容源的精华提取与重新编织(见下方章节映射表)
- 全局章节导航(目录/进度指示,可跳转任意章节)
- 沉浸式滚动场景演变 + 全套降级(reduced-motion / 移动端)

### Out of Scope

- **不改动任何既有页面**,index.html 必须零改动
- `playground.html`(技术实验)与 `replica.html`(主页副本)不作为内容源
- 不从站内任何页面链接到 `opus.html`(保持半私密;是否公开是后续独立决策)
- 不新增图片资产依赖(可复用 `assets/gallery/` 既有图,缺图必须有占位降级)
- 不做多页拆分、不做构建工具

## 内容与结构要求

### 体验要求

- 章节切换必须有**场景级**视觉变换(背景色温/光效/版式至少一项整体演变),而非仅元素入场动画
- "光"母题贯穿:各章的光效气质应随叙事推进演变(具体设计交给技术方案)
- 沿用站点设计系统(`:root` 暖金调色板、衬线中文标题、英文眉题),在此基础上做强化而非另起炉灶

### 技术倾向(PM 约束,非方案)

- 性能优先于特效堆砌:滚动必须流畅,宁可砍特效不可掉帧
- 体量控制:HTML 文件(不含图片)≤ 400KB
- 遵循 `docs/architecture.md` 全部硬约束

## 验收标准

PM 验收时逐条打勾,全过才算 done:

1. [ ] `opus.html` 存在且完全自包含;`git diff` 证明所有既有页面(尤其 index.html)零改动
2. [ ] 章节映射表 10 章全部存在,每章内容确实源于对应页面(抽查可溯源),无章节缺失
3. [ ] 章节顺序与映射表一致,叙事弧完整(序章开场、终章收束)
4. [ ] 至少 5 处章节切换具有场景级视觉变换(背景/光效/版式整体演变)
5. [ ] 全局导航可用:任意位置可查看当前章节位置,可跳转到任意章节
6. [ ] 1024 / 880 / 768 三档断点布局完整,移动端可完整阅读全部内容
7. [ ] `prefers-reduced-motion` 下全部内容完整可读,无依赖动画才能呈现的信息
8. [ ] 滚动动画仅使用 transform/opacity(或等效低开销手段),长页滚动无明显卡顿
9. [ ] HTML 文件体量 ≤ 400KB(不含图片)
10. [ ] 站内无任何页面链接到 `opus.html`;`opus.html` 使用站点 `:root` 调色板变量
