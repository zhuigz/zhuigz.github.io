# REQ-004 — 技术方案

## 方案概述
在现有单HTML内修改CSS及原生JS，添加固定阅读栏、原生details目录；用章节几何位置更新阅读指示，保持原生锚点和浏览器历史。正文默认可见，观察器只触发短暂入场效果。移除数字清零及全局键盘跳章。

## 关键决策
- 目录使用原生details，替代自定义弹窗：无JS仍可用，触点至少44px。
- 桌面沿用原侧栏；1100px以下显示目录，避免侧栏与正文挤在一起。
- 阅读导航不依赖观察器；观察器只增强可见正文，不承担可读性。
- 成绩直接呈现原数值，替代从0计数，避免误读及观察器失败导致错误值。
- 只标明历史记录时点，不推断用户现在的年龄、角色、指标或经历。
- 保留原字体、暖棕色和装饰；字体非阻塞加载并保留noscript回退。

## impact_scope
- ux_surface: yes — 导航、键盘阅读、窄屏时间轴及标题、动画显示。
- product_contract_change: no — 原文和原网址不变。
- structural_change: no — 保持单HTML、内嵌CSS/JS、无新增外部脚本。
- scope_tradeoff: yes — 此轮不补新事实，先完成阅读修复，视觉验收后发布。

## Phase / Task 拆解
### Phase 1：阅读与显示
- T1.1 六章原生目录、当前章节、回顶/主页与正常键盘滚动。
- T1.2 正文默认显示、数字原值、字体回退、减少动态效果。
- T1.3 记录时间标注、窄屏时间轴、光标收敛/离开/后台停帧。
### Phase 2：检查与验收
- T2.1 HTML/锚点/脚本语法/原文及数字一致性，源码DOM驱动运行模拟。
- T2.2 用户桌面/窄屏预览确认，解决发现的问题后合并，验证Pages。

## 风险与陷阱
- 不把历史“19岁生日前夕”的落款当作当前身份去改写。
- 不修改已经确认暂缓的页面及私人system。
- 本地file预览被内置浏览器URL安全规则拒绝；不绕过该规则。此轮仅源码检查及Node模拟，真实浏览器视觉、原生按键滚动、锚点落点和手机宽度仍待用户预览。未达到发布视觉门槛前不合并。
